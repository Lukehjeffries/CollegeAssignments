
Assignment Overview

- Objective: Build a simple end-to-end system that predicts how long a short, text-based task will take. The project demonstrates synthetic data generation, basic feature engineering, model training, and schedule creation.

- Inputs: Short task descriptions paired with estimated hours (text,label_hours) generated by training/generate_data.py.

- Outputs: A trained estimator (training/estimator.pkl) and time-based schedule suggestions produced by main.py.

- Scope and Limitations: This is a proof-of-concept using synthetic data and minimal features. It is not intended for production use. Possible extensions include richer text features (TF-IDF or embeddings), stronger validation, and more detailed model interpretation.

Project Structure

- README.md: Overview of the project and Project Questions

- features.py: Simple feature extraction (such as word and character counts).

- model.py: WorkloadEstimator class wrapping a scikit-learn regression model.

- main.py: Interactive program that estimates task duration and builds a schedule.

- tasks.py, schedule.py: Helper modules for loading tasks and generating schedules.

- training/generate_data.py: Script that creates training/data.csv from templated task descriptions.

- training/train_text_model.py: Trains the model using CSV data and saves the result.

- training/data.csv, training/estimator.pkl: Example outputs from the training pipeline.

Produced by the Pipeline

- training/model_results.csv: Summary of model evaluation results.

- training/estimator.pkl: Saved best-performing model.

- notebooks/outputs/: Exploratory data analysis visuals and summaries.

- explainability/outputs/: SHAP-based explanations


## Assignment Questions ##

What dataset was used, and why was it selected? Address data sources and any bias or ethical considerations.

- An artificial dataset generated with training/generate_data.py was used to create a controlled and repeatable text-to-hours prediction task. This approach was chosen because real, labeled task-time data is difficult to collect consistently. From an ethical standpoint, template-based generation can introduce phrasing bias, so the system avoids sensitive content. Any future use with real user data would require consent and careful handling..

What prediction task is being addressed, and why is it important?

- The task is a regression problem that predicts the estimated number of hours needed to complete a short, text-based task description. This is useful for lightweight planning, prioritization, and building realistic schedules.

Which models were tested, and what justified the final choice?

- The models evaluated included Linear Regression, Random Forest Regressor, and Multilayer Perceptron (MLP) Regressor. The final model selected was a Random Forest Regressor combined with a TF-IDF pipeline, as it consistently achieved the most reliable MAE and RMSE during cross-validation and works well with SHAP for interpretability.

How were the data processed and features engineered? Was normalization used, and why or why not?

- Text was converted into numerical features using a TfidfVectorizer, capturing individual words and optional two-word phrases with a capped feature size. Basic features such as word count and character count were also included. TF-IDF naturally scales features, and the Random Forest model does not require additional normalization. A StandardScaler was included in the pipeline for the Linear Regression and MLP baseline models, where scaling is more important.

What evaluation metrics and validation methods were applied?

- TThe primary evaluation metric was Mean Absolute Error (MAE), with Root Mean Squared Error (RMSE) used as a secondary metric. Models were evaluated using a 20% held-out test set and 5-fold cross-validation during model selection.

How was the model interpreted (for example, feature importance, PCA, SHAP, or LIME)?

- SHAP (TreeExplainer) for both overall and individual explanations, checked random forest feature importance as a quick sanity check, and optionally applied PCA to look for hidden structure. The results are explained in plain language in the explainability outputs.
